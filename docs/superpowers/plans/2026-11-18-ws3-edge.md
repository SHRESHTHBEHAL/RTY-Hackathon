# Workspace 3: Edge (Frontend, SDKs, Demo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build everything a person or an agent touches: the public website, the business and seller dashboards, the seller and agent SDKs, the MCP server, and the demo that is shown in the presentation.

**Architecture:** `@gaitway/sdk` is a dependency-light package with a seller side and an agent side, talking to the API over HTTP. The dashboard is a Next.js app whose every data call goes through one typed API client that can run on built-in fixture data or the live API. The demo is a small seller app plus an agent script, both using the SDK exactly as a customer would.

**Tech Stack:** Node 22, TypeScript 5, Vitest, jose, Next.js (App Router), Tailwind CSS, Playwright, Express (demo seller only), the official MCP TypeScript SDK.

**Spec:** `docs/superpowers/specs/2026-11-18-agent-payment-gateway-design.md` and `context.md`. Read both in full first. `context.md` sections 6, 7, 8, 10, and 11 are your contract.

## Global Constraints

- Edit only `packages/sdk/`, `packages/mcp/`, `apps/dashboard/`, `apps/demo/`, and `docs/handoff/ws3-notes.md`.
- Every route, field name, header, and error code comes from `context.md` section 8. Do not invent routes. If the dashboard needs data no route provides, write it in `docs/handoff/ws3-notes.md` and build without it.
- Amounts are micros strings on the wire and `bigint` in code. Display as dollars with two decimals, or up to six when the value is under one cent. Never do money arithmetic with floating point.
- `@gaitway/sdk` has `jose` as its only runtime dependency and works on Node 20 and later.
- The dashboard never puts a session token or API key in `localStorage` or in a URL. Sessions live in an `httpOnly` cookie set by Next.js server code.
- An API key is shown exactly once, at creation, with a copy button and a warning.
- Each owned directory must install, build, and test with no other workspace directory present. Until the real API exists, use the mock server (Task 1) and fixture mode (Task 5).
- The dashboard must be usable at phone width and pass keyboard navigation on every form.
- No crypto vocabulary in the interface. Say "balance", "top up", "payout". The words "USDC", "blockchain", "gas", and "wallet address" appear only on the seller payout-details screen and in developer docs.
- Tests first. Commit after every task.
- Finish every Milestone 1 task before starting Milestone 2.

## Review Focus

- The API is down or slow: every screen shows a clear error with a retry, never a blank page or an endless spinner. (Task 5, checked on every page)
- An agent's `fetch` gets a second 402 after paying: it must stop and throw, not loop. (Task 3)
- A seller's handler throws after the charge succeeded: the SDK must not charge again on the agent's retry of the same request. (Task 2)
- A very large balance or a sub-cent amount: the formatter shows it correctly and tables do not break. (Task 5)
- A user double-clicks "Top up" or "Allocate": one request is sent. (Task 6)

### Task 2: Seller SDK

**Files:** `src/seller.ts`, `src/seller-express.ts`; tests `test/seller.test.ts`, `test/seller-express.test.ts`.

**Interfaces:**
- Produces:

```ts
class GaitwaySeller {
  constructor(opts: { apiKey: string; sellerId: string; baseUrl?: string });
  verify(token: string): Promise<CredentialClaims>;        // local check, cached JWKS
  charge(input: { credentialId: string; amountMicros: string; final?: boolean;
    description?: string; idempotencyKey?: string }): Promise<{ charge: Charge; remainingMicros: string }>;
  getCredential(id: string): Promise<Credential>;
  paymentRequired(price?: { priceMicros?: string; priceNote?: string }): { status: 402; body: object };
}
type CredentialClaims = { credentialId: string; agentId: string; agentName: string;
  business: { id: string; name: string; email: string; verified: boolean };
  maxMicros: string; expiresAt: Date; env: "test" | "live" };

function gaitwayExpress(seller: GaitwaySeller,
  opts: { priceMicros: string; priceNote?: string; description?: string }): express.RequestHandler;
// On success sets req.gaitway = { claims: CredentialClaims; charge: Charge; remainingMicros: string }
```

- [ ] **Step 1: Write failing tests:**
  - `verify` accepts a token from the mock and returns the mapped claims.
  - `verify` rejects: a token for another seller; an expired token; a token signed by an unknown key; a token with `alg: "none"`; a token whose `typ` is not `gaitway-credential+jwt`. Each throws `GaitwayError` with code `invalid_credential`.
  - `verify` fetches the JWKS once across 50 calls, and refetches once when it meets an unknown `kid`.
  - `charge` without an `idempotencyKey` generates one; with one, sends it.
  - `paymentRequired({ priceMicros: "10000", priceNote: "per message" })` returns the exact 402 body from `context.md` section 7.
  - Middleware, no header: replies 402 with that body; the handler does not run.
  - Middleware, valid token: charges `priceMicros` first, then runs the handler with `req.gaitway` set.
  - Middleware, charge refused (`amount_exceeds_remaining`, `credential_expired`): replies 402; the handler does not run.
  - Middleware uses the request header `gaitway-request-id` as the idempotency key when present, so an agent retrying the same request is charged once.
- [ ] **Step 2:** Run; expected fail.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run; expected pass.
- [ ] **Step 5:** Commit: `feat(sdk): seller side`.

### Task 3: Agent SDK

**Files:** `src/agent.ts`; test `test/agent.test.ts`.

**Interfaces:**
- Produces:

```ts
class GaitwayAgent {
  constructor(opts: { apiKey: string; baseUrl?: string; sessionMicros?: string /* default "1000000" */ });
  balance(): Promise<Wallet>;
  createCredential(input: { sellerId: string; maxMicros: string; ttlSeconds?: number }): Promise<Credential>;
  release(credentialId: string): Promise<Credential>;
  releaseAll(): Promise<void>;
  payments(): Promise<Charge[]>;
  fetch(url: string, init?: RequestInit, opts?: { maxMicros?: string }): Promise<Response>;
}
```

- [ ] **Step 1: Write failing tests** against the mock plus a tiny seller built with Task 2's middleware:
  - `fetch` to a paid route with no open session: receives 402, reads `gaitway.sellerId`, creates a credential for `sessionMicros`, retries with `gaitway-token`, returns the 200.
  - A second `fetch` to the same seller reuses the credential: no new credential is created.
  - When the credential is exhausted or expired, the next `fetch` creates a new one and succeeds.
  - A second 402 after paying throws `GaitwayError` with code `payment_failed`; no third attempt is made.
  - A 402 without a `gaitway` object is returned to the caller untouched.
  - Each logical call sends one `gaitway-request-id`, the same on the retry.
  - When `sessionMicros` exceeds the balance, the session is opened for the whole available balance; with zero balance it throws `insufficient_funds`.
  - `releaseAll` releases every open credential and the wallet's held balance returns to zero.
- [ ] **Step 2:** Run; expected fail.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run; expected pass. Write `packages/sdk/README.md` with a seller quickstart of at most 20 lines of code and an agent quickstart of at most 10.
- [ ] **Step 5:** Commit: `feat(sdk): agent side`.
