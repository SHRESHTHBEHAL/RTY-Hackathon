# Workspace 1: Vault and Dwarpal Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the smart contract that holds Gaitway's money, the TypeScript client the API uses to drive it, and the bridge that lets Dwarpal pay through Gaitway.

**Architecture:** One Solidity vault holds USDC with a balance per business. Privileged roles register addresses, settle seller batches, and process withdrawals; replayed batches are rejected by key. `@gaitway/chain` wraps the contract behind the `VaultClient` interface so the API never touches viem directly.

**Tech Stack:** Solidity ^0.8.24, OpenZeppelin Contracts v5, Foundry, anvil, TypeScript 5, viem, Vitest. Bridge: Python, FastAPI, httpx, pytest (Dwarpal's existing stack).

**Spec:** `docs/superpowers/specs/2026-11-18-agent-payment-gateway-design.md` and `context.md`. Read both in full first. `context.md` sections 6, 9, 10, and 14 are your contract.

## Global Constraints

- Edit only `contracts/`, `packages/chain/`, `docs/handoff/ws1-notes.md`, and the `gaitway-bridge` branch of a separate Dwarpal checkout.
- The Solidity interface, events, role names, and `VaultClient` types in `context.md` section 9 are fixed. Copy them verbatim.
- Amounts are `uint256` micros on-chain and `bigint` in TypeScript. USDC has 6 decimals.
- Chain keys are `keccak256` of the identifier's UTF-8 bytes.
- `EXIT_DELAY` is 7 days.
- `packages/chain` must install, build, and test with only `contracts/` beside it.
- Package name `@gaitway/chain`. Node 22, pnpm 9, ES modules, `strict` TypeScript.
- No secrets committed. Provide `.env.example`.
- Tests first. Commit after every task.
- Finish every Milestone 1 task before starting Milestone 2.

## Review Focus

- A settle batch is retried after a crash: the second call must not pay twice. (Task 2, Task 5)
- A batch contains one bad item among good ones: nothing in the batch may move. (Task 2)
- The contract is paused while a business is exiting: the exit must still work. (Task 7)
- A token transfer that returns false or takes a fee: balances must not drift from the token balance. (Task 2: use `SafeERC20`, credit by measured balance change.)
- A deposit is seen, then removed by a chain reorganisation: `getDeposits` must only report blocks at or below `getConfirmedBlock`. (Task 5)
